# B 站刷视频 / 分享

> **2026-11-01 定稿**：B 站只有这一套（`qq_bili_share` + 定时自动分享 + 控制台候选预览），外部看视频插件已经卸掉。

QQ 端的机器人可以自己刷 B 站、按你的要求找视频，然后把视频发到群或私聊。

## 分享长什么样

两种场景，发法不一样：

- **自动分享（定时/随机刷到的）**：先发一条引入句，再发「封面 + 标题/链接/BV 号」——两条消息，中间隔 0.6 秒。
  引入句会沾一点这条视频的内容（从标题/标签里取话题），不是通用套话。
- **按需查找 / 上下文顺手推**：bot 先像平常一样回你一句（顺着你那句话，起个引子作用），然后再发「封面 + 标题/链接/BV 号」。
  这条工具本身不再单独发引入——引入由模型自己说，避免模板腔。

两条/一条都走 `sendChain` 串行发送，顺序不会乱。

> 为什么不用 QQ 小程序卡片：bilibili 的 QQ 小程序卡片只能由 QQ 服务端签发（SnowLuma 走的是
> PC 小程序分享通道 `V1_PC_MINISDK_99.99.99_1_APP_A`），手机上点开会提示「该小程序内测中」；
> 手拼 `com.tencent.structmsg` 链接卡会被判「发送者版本过低，无法展示内容」。
> 改 Ark 字段会被 QQ 服务端签名校验丢弃，所以最终走「图片 + 文本」这条路。

## 设置面板

浏览器打开：

```
http://127.0.0.1:3100/bili?token=<控制台令牌>
```

令牌在 `state/console-token`（也可从控制台首页 `http://127.0.0.1:3100/?token=…` 拿）。保存后立即生效，不用重启。

可配置项：

| 项 | 说明 |
| --- | --- |
| 引入语 | 自动分享的固定引入句；留空则按视频标题/标签自动拼一句相关的 |
| 定时自动分享 | 开关、目标会话（`group:群号` / `private:QQ号`，逗号分隔） |
| 最小/最大间隔 | 每轮结束后在这两个值之间随机取一个，不固定节奏（默认 90~210 分钟） |
| 取视频来源 | `hot` 热门、`recommend` 推荐流（需登录）、`interest` 按喜好搜、`ranking` 排行榜、`mixed` 并行混合（推荐+喜好占大头，混一点热门和排行） |
| 混合权重 | 只在 `mixed` 下出现：推荐 / 喜好 / 热门 / 排行 四路各占多少（相对权重，0 = 不参与） |
| 上下文智能推送 | 从聊天里嗅需求、后台找一条相关视频挂进唤醒提示，由 bot 自己判断推不推 |
| 每天最多几条 | `0` = 不限；按当日已分享条数计 |
| 去重时长 | 同一视频多久内不重复分享（小时，默认 168 = 一周，最长 8760 = 一年）；BV 号相同算重复，标题一字不差（换号搬运）也算。同类、同系列、同一个 UP 的其它视频不算重复 |
| 新鲜度加权 | 优先推新的：超过「只推这么多天内的」一律剔除（0 = 不限年代），剩下的按 0.5^(视频天数 ÷ 半衰期) 加权随机，老视频的权重最低衰减到「老视频最低权重」 |
| 活跃时段 | 只在这个区间自动分享（支持跨零点，起止相同 = 不限） |
| 自动分享引入语 | 定时分享专用；留空则用视频标题/标签拼一句沾边的话 |
| 喜好 | 是否记录、最多记几个词；显示已记录关键词 |
| 匹配方式 | 标签权重 / 标题权重 / 每个关键词补多少个标签；标签权重高则冷门但标签对得上的视频排前面 |
| 限流 | 请求最小间隔（默认 400ms）、突发额度、单次超时 |
| B 站账号 | 扫码登录 / 退出；登录后可用推荐流 |
| 写入观看历史 | 登录后把每次分享的视频写进该账号的「历史记录」（默认开） |

「现在分享一条」按钮会立刻挑一个没分享过的视频发出去，不用等定时器；面板底部还列着最近发过哪些。

## 匹配方式：标题 + 标签怎么打分

把关键词交给 B 站搜索接口后，候选会再排一次序：

- 标题里出现关键词：+ 标题权重（默认 1）
- 标签完全等于关键词：+ 标签权重 × 1.5（默认 2.5 → 3.75）
- 标签包含关键词（或反过来）：+ 标签权重

标签是 `x/tag/archive/tags` 单独拉的，匿名可取，结果缓存在 `state/bili-tags.json`（7 天）。
只看命中，不看播放量，所以播放几万但标签对得上的冷门视频也能排到前面。
标签权重填 0 就完全按 B 站原顺序。

## 喜好是怎么学到的

`qq_bili_share` 每次带 `query` 搜索时，关键词会被记进 `state/bili-interest.json`（同一词累加次数，按次数排序，再按最近一次像模像样地排）。自动分享用 `mode=interest` 时，会从记得的关键词里随机挑一个去搜，挑没分享过的视频。`mixed` 模式里，「喜好」这一路就是这么来的。

几个边界：

- 只记「你自己给的词」——`query` 传了关键词才记；`hot` / `ranking` / `recommend` 和 `interest`、`mixed` 内部那几路自动搜的词不记，否则会自我循环、越搜越偏。
- 传 `bvid` / 链接直接要某条视频的不记。
- 关键词会先被拆成「像 B 站标签」的短词条（2026-11-02 用户要求）：按空格、逗号、顿号、斜杠和各种标点切；相邻英文词合并（`BanG Dream`、`Hololive EN` 算一个）；去停用词（视频 / 推荐 / 合集 / up主…）、纯数字和单字；每个词最多 `bili.interest.maxLen` 个字（默认 10），超过这个长度的一律不记（截断只会截出半句话）；一次搜索最多拆 `bili.interest.maxPerQuery` 条（默认 3）。
- 例：「BanG Dream 少女乐团派对 难度29 手元 全连」→ `BanG Dream` / `少女乐团派对` / `难度29`；「帮我找一下有没有明日方舟的攻略视频」这种整句太长，什么都拆不出来，就不记。
- 上限取 `bili.interest.maxKeywords`（面板「喜好」那一行的「最多记几个词」），超过就截掉次数最低的；代码里再兜一个 40 条的硬顶。
- `bili.interest.enabled` 关掉之后整个词库不再写入，已有的词留着继续参与推荐——想清空就删 `state/bili-interest.json`。

## 手动改喜好

控制台「B 站」页（`/bili`）的「喜好推荐」里，记下的词可以点词本身改名、点 × 删掉、下面的输入框加新词。改动立刻写进 `state/bili-interest.json` 并生效，不用点「保存设置」，也不用重启。

- 改名时如果新词原来就在列表里，会合并、沿用原来的次数记录。
- 手动加的词同样受 `bili.interest.maxKeywords` 限制，满了面板会拦下来提示。
- 手动词按同一套规则收一遍（拆第一个合格标签、超长不收），所以粘一整句进来只会留下最前面那个短词。
- `interest.enabled` 关掉只拦「自动记录」，手动编辑照常能写——关掉之后想留着词就自己加。

## 上下文智能推送

聊天里出现疑问/想找东西的信号（`？`、`怎么`、`有没有`、`推荐`、`帮我找` 等）时，桥接会在后台：

1. 从这句话里抠出关键词（去掉「有没有」「推荐一下」「教程」这类噪声），
2. 以一定概率（面板「命中信号时的试推概率」，默认 0.5）去 B 站搜一条相关视频，
3. 把候选挂进这个会话的缓存，在下一次唤醒提示里附一段【可选推送素材】，并标上「同话题近 24h 提了几次」。

**它不会自动发**：由模型自己判断这个视频是不是真帮得上，决定推不推、引入怎么写——先接住用户刚才那句話，再说视频。不相关就一直放着（缓存 20 分钟过期）。
限频是「同一会话最短间隔」（默认 30 分钟，面板可调 30s~1h），避免刷屏。

## 三种场景，引入怎么来

| 场景 | 引入怎么写 | 发几条 |
| --- | --- | --- |
| 定时/随机推荐 | 代码自动拼：从视频标题或标签里取话题，套进 `INTRO_TEMPLATES`（如「这个「明日方舟」的视频我觉得你会喜欢。」）；面板配了固定引入语就优先用它 | 引入一条 + 视频一条 |
| 用户点名让你找 | 模型先正常回一句（顺着对方的话，不套模板），再发视频 | 回话一条 + 视频一条 |
| 上下文顺手推 | 模型先回他那句话再发视频，不要把【可选推送素材】的说明念出来 | 回话一条 + 视频一条 |

## 登录 B 站账号（可选）

面板上点「扫码登录」，用 B 站 App 扫码即可。凭据存 `state/bili-credential.json`（只在本地）。

- 登录后：自动分享可用 `recommend` 模式，刷的是该账号的推荐流。
- 登录后默认会把分享过的视频写进账号的「历史记录」（web 端心跳接口 `x/click-interface/web/heartbeat`，
  带 aid + 几十秒进度），所以在 B 站 App 的「历史」里能看到 bot 替你刷过什么。
  不想留痕就在面板上关掉「写入观看历史」。纯取数接口（热门/搜索/详情）本身不产生观看记录。
- 不登录：热门 / 搜索 / 排行都能用，只是没有个性化推荐。
- 登录态失效时面板会标红，重新扫码即可。

## 防「吃 token / 吃额度」

- 所有 B 站请求都过 `TokenBucket`（默认 400ms/次、突发 4 次），并带 TTL 缓存与单飞去重。
- 自动分享有每日条数上限（`autoShare.maxPerDay`，0 = 不限）。
- 同一视频按 `dedupeHours` 去重（默认一周）：BV 号相同，或标题完全相同（换号搬运）；同类视频不挡。候选里全推过就这一轮不发，**不会退回「随便给一条」**——之前的重复推送就是这么来的。
- 喜好模式下同一个关键词会随机翻到第 1~3 页，所以「前十条推完了」不等于这类推完了，同类的新视频还能接着来。
- 新鲜度默认只推一年内的，并按半衰期加权偏向新视频（见 `autoShare.freshness`）。
- 只走匿名通道取数，分享不需要登录；登录只在启用 `recommend` 时才起作用。

## 给模型用的工具

`mcp__snowluma__qq_bili_share`

| 参数 | 说明 |
| --- | --- |
| `key` | 会话 key：`group:群号` / `private:QQ号` |
| `token` | 会话令牌 |
| `query` | 关键词找视频（会记进喜好） |
| `bvid` | 直接指定 BV/av/链接 |
| `mode` | `hot` / `ranking` / `search` / `recommend` / `interest` / `mixed` |
| `list` | `true` = 只列候选不发送（纯文字：标题/UP/播放/链接） |
| `limit` | 候选数量 |
| — | 没有 intro 参数：工具只发封面 + 标题/链接/BV，引入先用 `qq_send_message` 自己说一句 |

只有这一个 B 站工具。之前试过的那版外部插件（14 个 `bili_*`）已经整体卸载，临时的 `qq_bili_look`（读简介/热评）也连工具带路由一起删了。

### 候选预览：只在控制台看

`/bili?token=…` 页面新增「候选预览」：选来源（混合 / 推荐流 / 按喜好 / 热门 / 排行）、可填关键词、点「看看候选」，下面是带封面缩略图的卡片墙（点开跳 B 站）。

- 数据走 `POST /api/bili/candidates`（只认控制台令牌，带 `x-agent-token` 会被 403 挡住——刻意不让模型拿到这条路）。
- 封面走 `GET /api/bili/cover?u=<B站图床地址>` 代理：B 站图床有防盗链，直接 `<img>` 会 403；只放行 `hdslb.com`，避免变成任意 URL 读取口。
- **不会发给模型、也不会发到群里**：想真发，用上面的「现在分享一条」，或让群里的她自己发。
